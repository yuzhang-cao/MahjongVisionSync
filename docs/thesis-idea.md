# 基于多 iOS 终端协同感知的麻将比赛牌局状态识别与实时概率分析系统的设计与实现

## 1. 选题定位

本课题拟设计并实现一套面向麻将比赛场景的实时牌局数据采集与分析系统。系统通过多台 iOS 终端从不同角度对牌桌进行感知，利用摄像头采集、图像识别、多端协同同步与概率分析算法，对比赛中的牌局状态进行自动识别、重建和实时分析。

本系统的使用对象为赛事组织方、裁判人员、转播数据人员和赛后复盘人员，不面向参赛选手提供实时决策辅助。系统输出结果主要用于赛事记录、转播展示、裁判辅助和赛后数据分析。

## 2. 研究背景

麻将比赛具有信息密集、状态变化快、人工记录难度高等特点。传统比赛记录主要依赖人工观察、手动录入或赛后整理，存在以下问题：

- 记录效率低，难以完整保存比赛过程。
- 人工记录容易漏记、错记，影响赛后复盘准确性。
- 转播展示缺少实时数据支撑，观众难以直观看到牌局变化。
- 裁判在争议回看和牌局核验时缺少结构化数据辅助。

随着移动设备性能提升，iOS 终端已经具备较强的图像采集、端侧机器学习推理和近场通信能力。利用多台 iOS 设备进行协同感知，可以在不依赖昂贵专用硬件的情况下，实现对麻将比赛牌局状态的自动识别与实时分析。

## 3. 研究意义

### 3.1 实际应用意义

本课题可以为麻将赛事提供低成本的数据化采集方案，减少人工录入工作量，提高比赛记录的实时性和准确性。系统生成的牌局状态和概率分析结果可用于赛事转播、裁判辅助和赛后复盘，提升比赛的信息化水平。

### 3.2 工程实践意义

本课题综合涉及 iOS 应用开发、摄像头采集、CoreML 识别、多终端通信、状态融合、概率分析和实时 UI 展示，符合软件工程专业毕业设计对综合性、实践性和系统完整性的要求。

### 3.3 技术研究意义

本课题不是单纯实现一个麻将助手，而是围绕比赛场景中的多源感知、牌局状态重建和实时概率评估展开。其关键技术问题包括多终端数据同步、识别结果融合、牌局状态一致性维护和概率指标计算，具有一定研究和实现价值。

## 4. 系统目标

系统最终目标是实现一套可运行的 iOS 端麻将比赛牌局识别与分析原型系统，具备以下能力：

- 支持多台 iOS 终端接入同一牌局。
- 支持通过摄像头识别麻将牌面信息。
- 支持将不同终端识别到的数据同步到主控端。
- 支持对牌局状态进行统一重建和校验。
- 支持实时计算听牌、有效牌、剩余有效牌数量和概率趋势。
- 支持以可视化方式展示当前牌局分析结果。
- 支持保存牌局过程数据，供赛后复盘使用。

## 5. 系统使用场景

典型使用流程如下：

1. 比赛开始前，赛事工作人员在牌桌周围布置多台 iOS 设备。
2. 每台设备负责拍摄不同区域，例如玩家手牌区、弃牌区、副露区或全局桌面。
3. 各 iOS 终端通过局域网或近场通信加入同一个牌局会话。
4. 采集端持续识别牌面信息，并将识别结果发送给主控端。
5. 主控端融合多端数据，形成统一的牌局状态。
6. 系统根据当前牌局状态计算听牌情况、有效牌数量和概率趋势。
7. 分析结果提供给裁判、转播数据人员或赛后复盘人员查看。

## 6. 总体架构

系统可划分为四层：感知采集层、协同通信层、状态分析层和展示应用层。

```mermaid
flowchart LR
    A[多台 iOS 采集端] --> B[牌面识别模块]
    B --> C[协同通信模块]
    C --> D[主控端状态融合模块]
    D --> E[牌局状态重建模块]
    E --> F[实时概率分析模块]
    F --> G[裁判/转播/复盘展示界面]
```

### 6.1 感知采集层

负责调用 iOS 摄像头采集牌桌画面，并通过 CoreML 模型识别麻将牌类别、位置和置信度。

### 6.2 协同通信层

负责多台 iOS 终端之间的连接发现、会话建立、数据同步和异常处理。可采用 MultipeerConnectivity、局域网 Socket 或 WebSocket 方案。

### 6.3 状态分析层

负责将多端识别结果转换为统一的牌局状态，包括手牌、弃牌、副露、已见牌和当前回合信息，并对冲突结果进行校验和修正。

### 6.4 展示应用层

负责向赛事工作人员展示实时牌局状态、听牌情况、有效牌数量、概率分析结果和历史牌局记录。

## 7. 功能模块设计

### 7.1 iOS 牌面识别模块

- 调用 AVCaptureSession 采集实时画面。
- 使用 Vision/CoreML 进行麻将牌目标检测与分类。
- 输出牌面类别、位置、置信度和时间戳。
- 支持多帧识别和识别结果稳定化。

### 7.2 多终端协同模块

- 支持多个 iOS 终端加入同一比赛会话。
- 支持采集端向主控端发送识别结果。
- 支持设备编号、区域绑定和状态心跳。
- 支持断连提示和数据重传。

### 7.3 牌局状态重建模块

- 根据多端识别结果构建统一牌局状态。
- 维护手牌、弃牌、副露、已见牌等状态。
- 对非法状态进行校验，例如同一张牌超过 4 张。
- 对多端识别冲突进行置信度融合或人工确认。

### 7.4 实时概率分析模块

本课题中的“概率分析”主要指面向比赛转播和复盘的数据指标，不直接向选手提供决策建议。可包括：

- 当前是否听牌。
- 听哪些牌。
- 有效牌数量。
- 剩余有效牌数量。
- 摸入有效牌概率。
- 当前局势变化趋势。
- 基于简化模型的胡牌概率估计。

### 7.5 数据展示与复盘模块

- 展示当前牌局状态。
- 展示各玩家听牌和有效牌分析结果。
- 展示概率趋势变化。
- 保存关键事件，支持赛后回放和复盘。

## 8. 技术路线

### 8.1 开发平台

- 开发语言：Swift
- UI 框架：SwiftUI
- 采集框架：AVFoundation
- 识别框架：Vision + CoreML
- 多端通信：MultipeerConnectivity 或局域网通信
- 数据存储：本地 JSON / SQLite / CoreData

### 8.2 实现路线

第一阶段：完成单 iOS 终端的牌面识别和听牌分析。  
第二阶段：实现多 iOS 终端连接和识别结果同步。  
第三阶段：实现主控端牌局状态融合与校验。  
第四阶段：实现有效牌、剩余牌和概率趋势分析。  
第五阶段：完善展示界面、异常处理和数据保存。  
第六阶段：进行测试、性能评估和论文撰写。

## 9. 可行性分析

### 9.1 技术可行性

目前已有 iOS 端麻将识别和听牌计算基础代码，包含摄像头采集、CoreML 模型识别、手牌录入和胡牌/听牌判断逻辑。后续可在此基础上扩展多端通信、状态融合和概率分析模块。

### 9.2 设备可行性

iPhone 和 iPad 均具备摄像头、端侧推理和局域网通信能力，适合作为低成本比赛数据采集终端。实际毕设演示阶段可使用 2 至 3 台 iOS 设备模拟多终端协同场景。

### 9.3 工作量可行性

课题包含多个模块，但可以按阶段实现。若时间有限，可优先保证多端同步、牌局状态识别和基础概率分析三个核心功能，其他高级分析作为扩展功能。

## 10. 可能的创新点

- 将多台 iOS 设备用于麻将比赛牌局的多角度协同感知。
- 将端侧视觉识别与牌局状态重建结合，降低人工记录成本。
- 面向赛事转播和裁判辅助，提供实时概率分析和数据展示。
- 通过多端识别结果融合，提高复杂比赛场景下的识别稳定性。

## 11. 重点与难点

### 11.1 重点

- iOS 端实时牌面识别。
- 多终端通信与同步。
- 牌局状态重建。
- 听牌和概率分析算法。
- 面向比赛场景的数据展示。

### 11.2 难点

- 多设备识别结果的时间同步。
- 不同角度下牌面识别结果不稳定。
- 多端数据冲突时的状态融合。
- 麻将牌局状态合法性校验。
- 概率分析模型的合理简化。
